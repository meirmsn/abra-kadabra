# Devshop Reorganization — Template Separation (v1.2)

> Construction notes for the devshop repo reorganization. This document records
> what changed, why, and every detail that matters for understanding the new layout.
> Written during implementation on 2026-04-14.

## Problem

The devshop repo (abra-kadabra) root mixed project template material with devshop
tooling. Files like `turbo.json`, `pnpm-workspace.yaml`, and `tsconfig.base.json`
existed at root but served no purpose for devshop development (the devshop has no
`apps/` or `packages/` directories). New projects started by cloning the entire
devshop repo — the root WAS the template.

The ROADMAP v+ "Repo layout clarification" entry acknowledged this:

> The devshop repo root mixes several concerns without clear separation...
> Claude (and humans) trip over it.

Additional problems:

- The init checklist (mutable `[x]` checkboxes) lived in GUIDE.md, a reference
  document. State masquerading as documentation.
- `.devshop/templates/` held .tmpl files (BUILD-LOG.md.tmpl, etc.) in a flat
  directory separate from where they'd end up — an unnecessary indirection.
- No clear way to develop the devshop in its own devcontainer without risk of
  destructive symlink operations.

## Solution

### 1. `template/` directory at repo root

Created `/devshop/template/` containing the complete project skeleton — everything
a new project needs. The root was simplified to devshop-only concerns.

**What's in template/ (25 files):**

```
template/
├── .devcontainer/
│   ├── devcontainer.json     ← container config (identical to root .devcontainer/)
│   ├── Dockerfile            ← build recipe (identical to root)
│   ├── init-devshop.sh       ← thin forwarder → /devshop/.devshop/scripts/init-devshop.sh
│   ├── init-firewall.sh      ← generic domains only (no project-specific)
│   ├── checksums.sha256      ← binary integrity hashes
│   └── README.md             ← devcontainer docs
├── .github/
│   ├── workflows/ci.yml      ← CI pipeline
│   ├── workflows/keepalive.yml ← Supabase pause prevention
│   └── dependabot.yml        ← weekly npm security updates
├── .husky/pre-commit          ← lint-staged + turbo typecheck + gitleaks + .hooks/
├── BUILD-LOG.md               ← was .devshop/templates/BUILD-LOG.md.tmpl
├── PRODUCT-ROADMAP.md         ← was .devshop/templates/PRODUCT-ROADMAP.md.tmpl
├── README.md                  ← project README with <project-name> placeholders
├── turbo.json                 ← monorepo task definitions
├── eslint.config.mjs          ← ESLint flat config
├── tsconfig.base.json         ← shared TypeScript config
├── pnpm-workspace.yaml        ← apps/* + packages/*
├── package.json               ← full deps (turbo, eslint, vercel, etc.), name "project-name"
├── .gitignore                 ← project version (includes devshop injection ignores)
├── .editorconfig, .prettierrc, .prettierignore, .gitattributes
├── .gitleaks.toml, .npmrc, .nvmrc
```

No `pnpm-lock.yaml` in template — generated per-project by `pnpm install` during init
(projects add their own apps/packages which change the dependency tree).

### 2. `init-devshop.sh` moved to `.devshop/scripts/`

The real injection script moved from `.devcontainer/init-devshop.sh` to
`.devshop/scripts/init-devshop.sh`. All devshop scripts now live in one place.

Both `.devcontainer/init-devshop.sh` files (root + template) are thin forwarders:

```bash
#!/usr/bin/env bash
[ -f /devshop/.devshop/scripts/init-devshop.sh ] && exec bash /devshop/.devshop/scripts/init-devshop.sh
```

The NOPASSWD sudo chain works: `/usr/local/bin/init-devshop.sh` (baked in Dockerfile)
→ `/devshop/.devcontainer/init-devshop.sh` (thin forwarder) → `/devshop/.devshop/scripts/init-devshop.sh` (real script).

### 3. `/ak-init` replaced by `/ak-new-project` + `/ak-migrate-project`

**`/ak-new-project`** — single entry point with two phases:

- **Phase A** (runs from devshop or any project container): creates a GitHub repo
  via `gh repo create`, clones to /tmp, copies template/ into it, commits + pushes.
  Prints instructions to clone on host and open in VS Code.
- **Phase B** (runs inside the new project's container): detects template files
  present but no INIT-TRACKER.md → starts setup. Creates INIT-TRACKER.md for
  resume tracking. Walks through 25 steps (accounts, credentials, scaffolding,
  integrations, security).

Phase detection: `.devshop/` is real dir → Phase A. `INIT-TRACKER.md` exists →
resume Phase B. `turbo.json` exists but no tracker → Phase B first run.

**`/ak-migrate-project`** — skeleton with two tiers documented:

- Lightweight: same stack, merge configs, wire tooling
- Full: different stack, port everything

### 4. Init checklist moved out of GUIDE.md

GUIDE.md no longer has mutable `[x]` checkboxes. It's reference documentation only,
pointing to `/ak-new-project` skill for the full process.

Each project gets its own `INIT-TRACKER.md` at root, created by `/ak-new-project`
on first Phase B run. Contains the checklist with `[ ]` boxes. Stays as a permanent
record after init completes.

### 5. `.devshop/templates/` eliminated

The `.tmpl` files moved INTO `template/` at their final locations:

- `.devshop/templates/BUILD-LOG.md.tmpl` → `template/BUILD-LOG.md`
- `.devshop/templates/PRODUCT-ROADMAP.md.tmpl` → `template/PRODUCT-ROADMAP.md`
- `.devshop/templates/README.md.tmpl` → `template/README.md`
- `.devshop/templates/.github/dependabot.yml` → `template/.github/dependabot.yml`

`/ak-new-project` modifies these in-place after copying (fills `<project-name>`,
`<one-line description>` placeholders). No separate template processing step.

### 6. Devshop-self guards

When the devshop repo is opened directly in VS Code as a devcontainer, the workspace
IS the devshop (/workspace and /devshop point to the same directory via bind mounts).
Without guards, `init-devshop.sh` and `create-devshop-symlinks.sh` would create
symlinks that replace real directories — destructive.

Four scripts got devshop-self detection:

**`init-devshop.sh`** — after password setup, checks if `.devshop/` is a real dir
(not symlink). If so: installs deps, locks settings.json + .dcg.toml, exits early.
No symlinks, no copies, no memory symlink, no BUILD-LOG.md.

**`create-devshop-symlinks.sh`** — same check, exits immediately. Prevents
`ln -sfn /devshop/.devshop /workspace/.devshop` from replacing the real directory.

**`devshop-commit-guard.sh`** — repo detection used `GIT_ROOT` path matching
(/workspace = project, /devshop = devshop). In devshop-self mode, GIT_ROOT=/workspace
but the repo IS the devshop. Without the fix, Check 1 (mixed commits) would
false-positive on `template/` files (classified as PROJECT_FILES since they're
not in DEVSHOP_PATTERNS). Fix: check if `.devshop/` is a real dir before the
case statement.

**`.devshop/hooks/pre-commit.sh`** — same repo detection issue. In devshop-self
mode, would run PROJECT checks (including security-files-freshness) instead of
DEVSHOP checks. Fix: same real-dir detection.

The detection pattern is consistent across all four:

```bash
if [ -d "$WS/.devshop" ] && [ ! -L "$WS/.devshop" ]; then
  # Devshop-self mode
fi
```

### 7. Root package.json simplified

Removed: `turbo`, `vercel`, turbo-dependent scripts (`lint`, `typecheck`, `test`,
`test:unit`, `build`, `dev`), `pnpm.onlyBuiltDependencies`.

Kept: `eslint`, `@eslint/js`, `eslint-plugin-jsdoc`, `typescript-eslint`,
`typescript`, `husky`, `lint-staged`, `prettier`.

**eslint quirk**: `lint-staged` invokes `eslint --fix` on `*.{ts,tsx,js,jsx}` on
every commit. Removing eslint would break every devshop commit. Practically a no-op
(no .ts/.js files at devshop root) but removing it requires a different lint-staged
config at root vs template — unnecessary complexity. Documented in CLAUDE.md.

### 8. Husky pre-commit turbo guard

```diff
-pnpm turbo run typecheck
+[ -f turbo.json ] && pnpm turbo run typecheck
```

Same hook file works in both contexts:

- Devshop root (no turbo.json after move) → skip typecheck
- Projects (turbo.json exists) → run typecheck

### 9. Sync scripts updated

`sync-from-devshop.sh` and `sync-to-devshop.sh` now source from / target
`$DEVSHOP_DIR/template/$path` instead of `$DEVSHOP_DIR/$path`.

`manifest.txt` paths stay project-relative (`.gitignore`, `turbo.json`, etc.).
The scripts handle the `template/` prefix internally.

`sync-to-devshop.sh` LOCK_FILES updated to `template/.devcontainer/` paths.

### 10. Settings.json deny rules

Added:

```json
"Edit(/devshop/template/**)",
"Write(/devshop/template/**)"
```

Prevents Claude from modifying the project template directly. Changes flow through
projects → sync-to-devshop.sh → template/.

### 11. Init-devshop.sh locking loop

Updated devshop-side paths to lock files in both locations:

- Root `.devcontainer/` (devshop's own container config)
- `template/.devcontainer/` (project template)
- `.devshop/scripts/init-devshop.sh` (the real injection script)

BUILD-LOG.md fallback path updated from `.devshop/templates/BUILD-LOG.md.tmpl`
to `template/BUILD-LOG.md`.

### 12. Init-firewall.sh genericized

Both root and template versions now have only generic domains:

- Package managers (npm, Debian)
- APIs (Anthropic, Sentry, Supabase, Vercel)
- CDNs (jsdelivr, Playwright, fonts)
- VS Code marketplace
- Docker registries

Project-specific domains (Vercel app URL, Supabase project ref, Sentry org ingest,
PostHog ingest, Docker Hub) replaced with placeholder comments. `/ak-new-project`
step 6 guides adding them.

## Known considerations

### `.devcontainer/` duplication

Root and template `.devcontainer/` are identical (6 files). When updating (e.g., new
tool version in Dockerfile), BOTH must be updated. This is documented in CLAUDE.md
under "Devshop Repo Layout" and GUIDE.md under "Known gotchas". Consider a CI check
or sync script in the future.

### `template/` not in DEVSHOP_PATTERNS

Changes to `template/` files in the devshop repo don't trigger docs drift review
(Check 2 in devshop-commit-guard.sh). This is intentional — template changes are
build tooling updates, not operational changes. If this causes confusion, add
`'^template/'` to DEVSHOP_PATTERNS.

### Thin forwarder chain

The NOPASSWD sudo chain for init-devshop.sh is now three hops:

1. `/usr/local/bin/init-devshop.sh` — baked into Docker image at build time
2. `/devshop/.devcontainer/init-devshop.sh` — thin forwarder (from root or template)
3. `/devshop/.devshop/scripts/init-devshop.sh` — real injection script

Step 1 is baked at build time and cannot change without rebuilding the container.
It points to step 2 which is on the bind mount and can be updated. Step 2 points
to step 3 which is the real script with all the logic.

If the devshop repo is not mounted (public contributor without abra-kadabra),
step 2 is a thin forwarder in the project's own `.devcontainer/` that silently
no-ops (`[ -f ... ] && exec ...` — file doesn't exist, nothing happens).

### PRODUCT-ROADMAP.md genericized

The template version removed lalista-specific items:

- Removed: "Dependabot for dependency updates" (now in template/.github/dependabot.yml)
- Kept: PWA caching, visual regression, performance baselines, changesets, offline
- All items are generic web app concerns, not project-specific

## Migration from v1.1.x

For existing projects (if any existed):

1. Run `sync-from-devshop.sh` — pulls updated build tooling from `template/`
2. The `.devcontainer/init-devshop.sh` thin forwarder is synced automatically
   (it's in the `.devcontainer/` manifest entry)
3. On next container start, the new init-devshop.sh chain works

No existing projects needed migration — lalista was the only project, and its
thin forwarder was updated as part of this refactor.
