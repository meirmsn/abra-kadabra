- [x] **W10.6.2** Independent reviewer script (locked-down `claude -p`, read-only repo tools, invoked by the done/open-PR check; 3 rounds → ask owner) — 2026-10-12 · PR #61 · LOG #29
  - Built to the interface below: [`runtime/reviewer/`](../../../../runtime/reviewer/README.md). `tests/reviewer.test.sh` (CI, stub `claude`) has 34 checks, and all 14 mutants are killed. `tests/reviewer-live.sh` ran the real reviewer on the A-04 fixtures 10 times per case: planted 10/10 fail on exactly AC-4, honest 10/10 pass. The honest fixture had to become runnable first (LOG #29). The hook that starts it is W10.4.4. The verdict on the PR is W10.6.3. Precision and recall are W10.6.5.
  - **Interface** (2026-10-12, proposed first so W10.4.4's hooks can call it; the build follows it, and any change is made here first):
    - **Where:** `runtime/reviewer/review.sh`, beside its pinned `prompt.md`, `verdict.schema.json` and `settings.json`. A session runs the copy its project pins: `/opt/devshop-current/reviewer/review.sh`. Model, prompt, tools and permissions come only from those files. No variable or flag changes them; tests run a copy of the directory with a stub `claude` (TARGET Verify 3, F-HOOK-10).
    - **Call:** `review.sh --base <rev> --spec <path>`, run from the project's worktree root. Both arguments are required and nothing else is accepted. `--base` is the PR's base (e.g. `origin/main`). The reviewed diff is `merge-base(base, HEAD)..HEAD`. `--spec` is the change's spec file, repo-relative. It must exist at `HEAD` and name its acceptance items `AC-<n>`. Only committed `HEAD` is reviewed, so the verdict ties to a commit (L-25). Uncommitted changes give could-not-run.
    - **What it runs:** a fresh `claude -p --restricted --safe-mode` with no CLAUDE.md, skills, hooks or MCP. Its tools are Read, Grep, Glob and Bash, and in `dontAsk` mode Bash runs only the allowlist in `settings.json` (read-only git, test commands). It works in a throwaway clone of the two commits that has no remote. Afterwards the real worktree must be unchanged (`HEAD` and status), or the result is could-not-run. These steps are feedback, not a wall (TARGET Verify, "what this protects against").
    - **Order:** first the diff against the spec's intent, decisions and every `AC-<n>`, each with evidence; nothing trimmed and nothing added. Then the lenses that apply: tests, docs, code, security, and design/QA for UI.
    - **Exit codes:** `0` pass · `1` fail: fix the blocking findings, commit, re-run · `2` could-not-run, including bad arguments. It never counts as a pass and goes to the owner (L-09) · `3` ask-owner: still failing at round 3 or later.
    - **Stdout:** exactly one line: `REVIEW: <outcome> · round <n> · <b> blocking, <l> low · <commit12> · <verdict path>`. Diagnostics go to stderr. If the review stops before it knows where to write (bad arguments, not in a git worktree), the line says `could-not-run`, round 0 and path `-`, and no file is written.
    - **Verdict file:** `<git common dir>/devshop/reviews/<branch, "/" → "__">/<seq>-<commit12>.json`, plus `latest.json` (a symlink) in the same directory. It lives inside `.git`, so it is never committed and never dirties the tree. Putting it on the PR is W10.6.3's job.
    - **Verdict JSON** (`format: "devshop-review/1"`): `outcome` (`pass|fail|could-not-run|ask-owner`), `round`, `commit`, `base` (the merge-base), `branch`, `spec`, `reviewer` {`devshop` (version dir), `model`, `session_id`, `cost_usd`}, `acceptance` [{`item`, `met`, `evidence`}], `findings` [{`severity` (`high|medium|unsure|low`), `lens`, `item`, `file`, `what`, `fix`}], `blocking` and `low` (counts), `lenses` [{`lens`, `applies`, `note`}], `reason` (why could-not-run, else empty), `created`.
    - **Outcome rule:** decided by the script, not the model (L-13). The result is fail if an `AC-<n>` is unmet or any finding is not `low`, so `unsure` counts as medium (TARGET Verify 6). It is could-not-run if the model's output fails the schema, misses an `AC-<n>` or names one the spec lacks, or if `claude` is missing, errors or times out (15 min) (L-12). **Rounds** count the distinct failing commits on the branch since its last pass; could-not-run doesn't count. A fail at round ≥ 3 becomes ask-owner.
