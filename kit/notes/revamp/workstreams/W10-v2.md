  - **Interface** (2026-10-12, proposed first so W10.4.4's hooks can call it; the build follows it, and any change is made here first):
    - **Where:** `runtime/reviewer/review.sh`, beside its pinned `prompt.md`, `verdict.schema.json` and `settings.json`. A session runs the copy its project pins: `/opt/devshop-current/reviewer/review.sh`. Model, prompt, tools and permissions come only from those files. No variable or flag changes them; tests run a copy of the directory with a stub `claude` (TARGET Verify 3, F-HOOK-10).
    - **Call** (changed in W10.6.6, 2026-10-12: `--spec` dropped, the spec found from the diff, the PR's words as a file): `review.sh --base <rev> [--pr <file>]`, run from the project's worktree root. `--base` is required, `--pr` is optional, and nothing else is accepted. `--base` is the PR's base (e.g. `origin/main`). The reviewed diff is `merge-base(base, HEAD)..HEAD`. Only committed `HEAD` is reviewed, so the verdict ties to a commit (L-25). Uncommitted changes give could-not-run.
    - **The spec** is found, never passed: the one `*.md` file under the repo's top-level `specs/` that the branch adds, changes or renames in `merge-base..HEAD` (deletions don't count). It must name its acceptance items `AC-<n>`, else could-not-run. **Two or more** such files → could-not-run. **None** (a bug fix, or a devshop change working from a task line): there are no acceptance items, and the intent comes from the PR's own words (title, summary, "what you should know") when `--pr` is given, else from the commit messages.
    - **`--pr <file>`**, the PR's words: a JSON file `{"title": "<string>", "body": "<string>"}`, the title non-empty. The W10.6.7 hook builds it with `runtime/reviewer/pr-words.sh` (one canonical line: other keys dropped, a null body as `""`) from the tool call it intercepts; on a push to an open PR, which carries no title or body, it reads them from the PR first. Unreadable, not JSON, other keys, an empty title or a non-string value → could-not-run. Given, the reviewer also checks the title and body against the final commit (Review 5): every claim true of the diff, nothing the diff does left out. The words reach the model inside the prompt, marked as data; they are never written into the clone.
    - **What it runs:** a fresh `claude -p --restricted --safe-mode` with no CLAUDE.md, skills, hooks or MCP. Its tools are Read, Grep, Glob and Bash, and in `dontAsk` mode Bash runs only the allowlist in `settings.json` (read-only git, test commands). `settings.json` is the one source of that list (W10.6.8): `review.sh` writes its `Bash(<command>:*)` entries into the prompt at `{{COMMANDS}}`, so the prompt names exactly the commands allowed; an allowlist it can't read, a `Bash` entry of another shape or an empty one is could-not-run. It works in a throwaway clone of the two commits that has no remote.
