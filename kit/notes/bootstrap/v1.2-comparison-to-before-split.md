# v1.2 Comparison: Before vs After Devshop Separation

> Deep analysis comparing the devshop infrastructure on the `main` branch (before
> separation) against `chore/separate-devshop` (after separation). Written
> 2026-04-14 to verify completeness of the split.

## Architecture Change

| Aspect              | Main branch (before)                                                                | Separated branch (after)                                                                                               |
| ------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Devshop location    | Embedded in project repo (`.devshop/` tracked in git)                               | Separate repo at `/devshop`, symlinked into workspace                                                                  |
| Skills              | SKILL.md files tracked in project git                                               | Symlinks to `/devshop/.claude/skills/`                                                                                 |
| Settings            | Tracked in git as `.claude/settings.json`                                           | Root-owned copy from devshop (gitignored)                                                                              |
| CLAUDE.md           | Single file: devshop conventions synced from `.devshop/CLAUDE.md` + project content | Split: project-only at `/workspace/CLAUDE.md`, devshop at `/devshop/CLAUDE.md` (auto-loaded via additionalDirectories) |
| Template sync       | Mount at `/template-repo`, scripts `sync-to-template.sh`/`sync-from-template.sh`    | Mount at `/devshop`, scripts `sync-to-devshop.sh`/`sync-from-devshop.sh`                                               |
| Init mechanism      | `init-devshop.sh`: password setup + lock 8 files                                    | `init-devshop.sh`: password setup + symlink creation + memory symlink + dep install + lock 22+ files + sticky bit      |
| Devcontainer mount  | `abra-kadabra` → `/template-repo` (read-only sync target)                           | `abra-kadabra` → `/devshop` (active injection source)                                                                  |
| `postCreateCommand` | Creates memory dirs + symlink                                                       | Onboarding skip only (memory moved to init-devshop.sh)                                                                 |
| Env vars            | `NODE_OPTIONS`, `GSTACK_STATE_DIR`                                                  | Same + `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`                                                                |

5. Pre-commit: lint-staged, typecheck, gitleaks, unified commit guard (mode-aware)
6. Post-commit: dirty state check, PR description check

### Pre-commit (.husky/pre-commit)

```bash
# Recreate devshop symlinks if missing
[ ! -L .devshop ] && [ -d /devshop/.devshop ] && bash /devshop/.devshop/scripts/create-devshop-symlinks.sh 2>/dev/null || true

pnpm exec lint-staged
pnpm turbo run typecheck
gitleaks protect --staged --redact
if [ -x .hooks/pre-commit ]; then bash .hooks/pre-commit; fi
```

The `.hooks/pre-commit` symlink points to `/devshop/.devshop/hooks/pre-commit.sh`,
which detects mode (project/devshop/devshop-self) and runs:

- check-security-files-freshness.sh (project only)
- check-clean-tree.sh
- devshop-commit-guard.sh (4 checks: mixed commits, docs drift, doc consistency, cross-repo dirty)

2. **All hooks** — DCG, memory guard, commit guard, dirty tree, PR description, session start

### Intentional Changes (not gaps)

1. **`/ak-init` → `/ak-new-project` + `/ak-migrate-project`**: The init skill was a
   single-project checklist. Replaced by two focused skills. `/ak-new-project` handles
   Phase A (template repo creation) and Phase B (interactive setup). `/ak-migrate-project`
   is a skeleton for existing projects — correctly deferred until a second project needs it.

2. **`check-clean-tree.sh` moved from PreToolUse to pre-commit chain**: On main, it ran
   as a PreToolUse hook (before git processes the command). On separated, it runs inside
   the unified `.devshop/hooks/pre-commit.sh` called by husky. Functionally equivalent —
   both block the commit. The PreToolUse slot now hosts `check-hook-bypass.sh` instead.

3. **Devshop conventions removed from project CLAUDE.md**: This is the whole point of the
   separation. Project CLAUDE.md is 60 lines of project-specific content vs 157 lines of
   synced conventions on main.

4. **Manifest patterns simplified in devshop-commit-guard.sh**: Main had 16 patterns
   matching specific devshop files (`.devshop/`, `.claude/settings.json`,
   `.claude/skills/devshop/`, etc.). Separated has 3 patterns (`^\.devshop/`, `^\.claude/`,
   `^\.dcg\.toml$`). Correct — in the separated branch, all these paths are gitignored
   in the project repo. The guard only needs to catch accidental staging of symlinks/copies.

5. **OVERVIEW.md renamed from README.md**: `.devshop/README.md` renamed to
   `.devshop/OVERVIEW.md` per commit `536fd5b`. All CLAUDE.md/GUIDE.md cross-references
   updated.

6. **Devshop-commit-guard.sh rewritten**: From 3 deterministic checks (mixed commits,
   docs drift detection, README/GUIDE sync) to 4 checks with 2 semantic checks requiring
   adversarial review (docs drift, doc consistency) and 1 cross-repo awareness check.
   The adversarial review uses a Sonnet agent to verify bypass reasons aren't glib or
   inaccurate.

## Security Analysis

### Improvements

- File locking expanded from 8 to 22+ files including devshop repo AND template
- Sticky bit on `.claude/` prevents deletion of root-owned files
- `check-hook-bypass.sh` blocks 3 bypass vectors with adversarial review
- `devshop.humanReviewed` flag reserved for human-only terminal use (blocked by PreToolUse for Claude)
- `check-security-files-freshness.sh` verifies copies aren't stale
- Deny rules expanded to cover devshop repo paths, scripts, template, and husky
- `settings.local.json` now root-owned (was unprotected on main)

### Remaining Known Vulnerabilities (carried from main)

1. **Fakeowner mount limitation**: On Docker Desktop macOS, `chown root:root` is cosmetic —
   kernel doesn't enforce it. Documented in ROADMAP.md. Separated branch mitigates better
   with sticky bit and expanded deny rules, but the fundamental limitation remains.

2. **Bash subshell bypass**: Bash commands can modify root-owned files via subshells
   (`python3 -c "open('file','w')"`) on fakeowner mounts. Edit/Write deny rules don't
   cover this. Documented in ROADMAP.md as v+ research item.

3. **Adversarial review API dependency**: If Claude API is unavailable,
   `adversarial-review.sh` requires human terminal access
   (`! git -c devshop.humanReviewed=... commit`). Fails closed — correct behavior, but
   means commits can be blocked during API outages.

## Remaining Concerns

1. **`/ak-migrate-project` is a skeleton**: Won't work until a second project needs the
   devshop. Acceptable for now — explicitly noted as deferred.

2. **`additionalDirectories` CLAUDE.md loading workaround**: Relies on
   `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` env var + manual injection in
   session-start.sh for anthropics/claude-code#22583. If the bug is fixed, the workaround
   can be simplified. If the env var behavior changes, the workaround may break.
   Low risk — tracked in session-start.sh comments.

3. **No CI for devshop repo**: The abra-kadabra repo has no CI workflow. Devshop scripts
   (commit guard, security checks, adversarial review) aren't automatically tested. gstack
   has its own CI, but devshop-specific scripts don't. Consider adding at least a
   shellcheck pass.

4. **Sync scripts renamed but not end-to-end verified**: `sync-to-devshop.sh` and
   `sync-from-devshop.sh` exist and reference `/devshop` instead of `/template-repo`,
   but haven't been exercised against a real sync cycle since the separation.

## Summary

The separation is **functionally complete and represents a net improvement** over main
in both security and functionality. Every capability from main is preserved or enhanced.
The architecture is cleaner — project repos are genuinely project-only, devshop
infrastructure lives in one place, and the symlink + root-owned copy model provides
resilience against git operations. The 5 new scripts close real gaps that existed on main.
The 2 new skills replace ak-init with a more flexible model. The 4 remaining concerns
are either tracked, low-risk, or correctly deferred.
