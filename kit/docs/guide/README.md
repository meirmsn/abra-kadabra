# Guide — routing index

This file is the **routing index** read by `/ak-spec` Step 1.5 and `/ak-implement` Step 1. Each row pairs a trigger signal (file-globs touched, keywords in Decisions, primitive imports) with a target — usually `(file, anchor)` into a specific guide section, sometimes a skill invocation, occasionally a full-file pointer.

> **Section anchors are tested** — `kit/tests/routing-link-resolution.bats` fails on any routing-row `(file, anchor)` that doesn't resolve to a real H2/H3. If you rename a guide section, update the routing index in the same commit.

**How to read the rows**: rows are grouped by domain (Data, Auth + security, Frontend + UI, Ops + deploy, Dev + meta). Targets prioritized per spec D4: `(file, anchor)` tuple > skill invocation > full-file. A spec or diff matches a row if any of its file-globs, primitive-import, or Decisions-keyword signals fire — heuristics are forgiving (file-globs preferred over exact paths; keyword matches against Decisions catch concept-touched-via-different-path cases).

**Promote-to-subdirectory rule (future migration)**: a logical group is promoted to its own subdirectory (`kit/docs/guide/<group>/`) when ≥3 files sustainedly belong to it AND cross-refs within the group outnumber cross-refs to outside it. Today no group meets the bar; flat layout with grouped index is intentional. When a group crosses the threshold, the routing index in this file is the single edit point — guides move under the new subdirectory, rows update their relative paths, BATS Test 1 catches any drift.

## Out of routing

These guides are NOT routed by `/ak-spec` Step 1.5 or `/ak-implement` Step 1 — they fire on a different cadence (project setup, host config, operator pipeline navigation) and don't usefully attach to a per-feature signal:

- [`architecture.md`](./architecture.md) — devshop-vs-project separation, init-devshop.sh, file lifecycle. Read on first project setup or when first navigating the codebase.
- [`macos-host-setup.md`](./macos-host-setup.md) — one-time per-Mac config (Docker Desktop hardening, `/etc/hosts`).
- [`workflow.md`](./workflow.md) — pipeline / skill maps. Operator-facing; read when picking the next skill. Out-of-routing for feature implementation work, but § Devshop Skill Map carries a paired one-paragraph reference back at the routing system so operators can discover the routing surface from the workflow side.

BATS Test 2 (`kit/tests/routing-completeness.bats`) asserts every guide in `kit/docs/guide/*.md` is listed either in a routing group above OR in this out-of-routing list — never both, never neither.
