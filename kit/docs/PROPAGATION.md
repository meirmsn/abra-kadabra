## v1.34.0

- **feat(conventions): require Existing projects block in devshop commits** — no project-side migration needed — convention governs
  devshop commit bodies only.
- **feat(template): ship rich Lev-scored PLAN.md schema to new projects** — `template/PLAN.md` is `[scaffold-once]` in
  `kit/manifest.txt` — `from-devshop.sh` won't propagate. lalista and
  home-os already have the rich schema (propagated manually during
  devshop PLAN.md evolution); verify with a diff and skip if current.
- **feat(sync): preview changes before applying in from-devshop and to-devshop** — no migration needed — scripts are consumed via the
  `.devshopkit` symlink, so projects get the new behavior on next container
  start (symlink resolves live). Operators will see the new y/N/diff prompt
  on their next `from-devshop.sh` or `to-devshop.sh` invocation.
- **feat(ak-build): auto-detect devshop mode and adapt pipeline** — no migration needed — devshop-only change, no
  template or project-side surface touched.
- **feat(template): keepalive pings Supabase directly + runs twice weekly** — home-os, lalista — scaffold-once file, not
  auto-synced. Copy the updated template step + cron line manually or
  via `from-devshop.sh` sync. Also add `SUPABASE_PROD_URL` +
  `SUPABASE_PROD_ANON_KEY` as GitHub Variables on each repo (both are
  public/anon-tier).
- **chore(build-log): record ak-build-devshop-mode + close tracker entries** — no migration needed — devshop-only tracker files.
- **feat(devcontainer): self-verifying Supabase CLI checksums + version pin** — After this lands, manually copy the updated Dockerfile
  and checksums.sha256 from the template into the project's `.devcontainer/`
  (the build fails before `init-devshop.sh` can propagate the locked files).
  After one successful rebuild, `init-devshop.sh` keeps them in sync.
- **feat(sync): show devshop version drift reminder on session start** — no migration needed — the bootstrap case (missing
  `.devshop-version`) shows the reminder automatically on next session start.
  Running `from-devshop.sh` creates the file and silences it.
- **feat(sync): auto-generate propagation log at release time** — no migration needed — PROPAGATION.md is populated
  by the next `release.sh` run. Projects see the hint after their next
  `from-devshop.sh` sync when the version changes.
- **fix(sync): preserve project identity + CI port + checklist gaps** — ci.yml and from-devshop.sh are `[sync]` — `from-devshop.sh`
  delivers both changes on next sync. Operator must also add one GitHub Variable
  manually: `SUPABASE_PROD_ANON_KEY` (project's anon key from Supabase dashboard ->
  Settings -> API). Currently affects: home-os, lalista.
