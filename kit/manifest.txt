# Shared files manifest — lists build tooling that lives in both repos.
#
# Paths are project-relative. Sync scripts map them to template/ in the devshop:
#   project: /workspace/<path>  <->  devshop: /devshop/template/<path>
# After init, files are owned by the project and can diverge.
# kit/scripts/sync/from-devshop.sh and kit/scripts/sync/to-devshop.sh read this list.
#
# NOT listed here:
# - Symlinked files (.devshopkit/, .claude/skills/, etc.) — always match devshop
# - Root-owned copies (settings.json, .dcg.toml) — copied on every container start
# - Project-only files (.env, settings.local.json)
# - Project orientation hierarchy scaffolded once at /ak-new-project time
#   (CLAUDE.md, PLAN.md, BUILD-LOG.md, PRODUCT-ROADMAP.md, TODOS.md, METRICS.md, README.md):
#   the template ships skeletons; projects own them after scaffold and diverge freely.
#   See kit/docs/guide/conventions.md § Project Docs Hierarchy.
# - Per-project hook exempt lists scaffolded once at /ak-new-project time
#   (.devshop-test-coverage-exempt, .devshop-docs-freshness-exempt):
#   same lifecycle as the orientation hierarchy — template ships an empty
#   stub with header comments; projects own them after scaffold and add
#   project-specific path entries. Bidirectional sync would clobber those
#   project-specific entries, so they're out of the manifest by design.
#   See kit/docs/guide/conventions.md § Test Presence + § Project Docs Freshness
#   for the conventions; check-test-coverage-project.sh + check-docs-freshness-project.sh
#   are the consumers.
# See kit/docs/guide/architecture.md § File Lifecycle for the full model.
